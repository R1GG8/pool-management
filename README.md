# REST API для организации работы бассейна (Pool Management API)

Тестовое задание на позицию Java Backend Developer (стажировка).  
Сервис предназначен для регистрации клиентов бассейна и управления записями на сеансы посещения.

---

## Стек технологий
* **Язык:** Java 21
* **Фреймворк:** Spring Boot 3.5.x (Spring Web, Validation)
* **База данных:** PostgreSQL 16
* **Слой данных:** **Чистый JDBC** (`javax.sql.DataSource`, `PreparedStatement`, `ResultSet`, `HikariCP`) - **без использования ORM / Hibernate / JPA**
* **Миграции БД:** Flyway (версии `V1` и `V2`)
* **Контейнеризация:** Docker (Multi-stage build) & Docker Compose
* **Документация:** OpenAPI 3 / Swagger UI (`springdoc-openapi`)
* **Тестирование:** JUnit 5, Mockito

---

## Реализованные требования и архитектурные решения

### 1. Обязательные требования:
- **Дискретность записи 1 час:** Запись возможна строго на целые часы (например, 10:00, 11:00). Запросы с некратным временем (10:15) отклоняются с кодом `400 Bad Request`.
- **Контроль рабочих часов:** Запись возможна строго в рабочие часы (по умолчанию с 08:00 до 22:00, последний слот стартует в 21:00). Настройки вынесены в `application.properties`.
- **Лимит вместимости (не более 10 человек в час):**
  Реализован на чистом JDBC с использованием **рекомендательных транзакционных блокировок PostgreSQL (`pg_advisory_xact_lock`)**. Это исключает состояние гонки (Race Condition) при одновременных параллельных запросах.
- **Чистый JDBC:** Все запросы написаны вручную через `PreparedStatement` с экранированием параметров (защита от SQL Injection). Ресурсы освобождаются автоматически через `try-with-resources`.
- **Нормализованная схема БД:** Первичные ключи клиентов создаются через стандарт `IDENTITY`, для записей используется `UUID`. Созданы частичные уникальные индексы (например, клиент не может иметь 2 активные записи на один час, но может перебронировать слот после отмены).

### 2. Необязательные пожелания - 100%:
- **Поиск по ФИО:** Эндпоинт `GET /api/v0/pool/clients?name=...` поддерживает фильтрацию по подстроке имени (регистронезависимо).
- **Отдельные графики для праздничных дней:** Таблица `holidays` (миграция `V2`) хранит кастомные расписания и выходные.
    - На 01.01 бассейн закрыт полностью (слоты не отдаются, бронь запрещена).
    - На 07.01 действует сокращенный рабочий день с 10:00 до 18:00.
- **Лимит 1 посещение в день:** Проверяется на уровне сервиса с оптимизированным запросом `SELECT 1 ... LIMIT 1`.
- **Запись на несколько часов подряд:** Эндпоинт бронирования принимает опциональное поле `durationHours` (1-4 ч). В рамках единой транзакции блокируются и резервируются все смежные часы сеанса. При отмене брони освобождается весь сеанс целиком.

## Запуск проекта

### Вариант 1. Запуск в Docker одной командой
Для запуска всего приложения и базы данных выполните:
```bash
docker compose up --build
```

(При первом запуске Docker скачает образы, выполнит многоэтапную сборку JAR через Maven и запустит сервис на порту 8080).
Интерактивная документация Swagger UI:
http://localhost:8080/swagger-ui.html

### Вариант 2. Локальный запуск
Запустите только базу данных:
```bash
docker compose up -d postgres
```
Запустите бэкенд локально:

Linux / macOS:
```bash
./mvnw spring-boot:run
```

Windows:
```bash
.\mvnw.cmd spring-boot:run
```

(Либо через запуск класса PoolManagementApplication в IDE).

### Вариант 3. Запуск без Docker (с локальным PostgreSQL)
Создайте пустую базу данных в вашей локальной СУБД:
```sql
CREATE DATABASE pool_db;
```
Запустите приложение с переопределением параметров подключения:

Linux / macOS:
```bash
./mvnw spring-boot:run -Dspring-boot.run.arguments="--spring.datasource.url=jdbc:postgresql://localhost:5432/pool_db --spring.datasource.username=ВАШ_ЮЗЕР --spring.datasource.password=ВАШ_ПАРОЛЬ"
```

Windows:
```bash
.\mvnw.cmd spring-boot:run -Dspring-boot.run.arguments="--spring.datasource.url=jdbc:postgresql://localhost:5432/pool_db --spring.datasource.username=ВАШ_ЮЗЕР --spring.datasource.password=ВАШ_ПАРОЛЬ"
```

### Тестирование
Проект покрыт набором изолированных юнит-тестов (JUnit 5 + Mockito), проверяющих все сценарии бизнес-валидации (дискретность, рабочие часы, лимит 10 мест, 1 визит в день, праздничные дни, бронь нескольких часов).

Запуск тестов:
Linux / macOS:
```bash
./mvnw test
```
Windows:
```bash
.\mvnw.cmd test
```
